# Ошибка в алгоритме D

Markdown-копия статьи Новака Калуджеровича **[A long division story](A-long-division-story.md)**
([оригинал](https://kolja.rs/algorithm-d)) — об ошибке в алгоритме 4.3.1D из «Искусства
программирования» Кнута (деление в столбик), прожившей с 1995 по 2026 год.

Алгоритм D делит огромные числа по одной цифре. Каждую цифру частного он *угадывает*, а
потом поправляет догадку не более двух раз. В книге доказано, что догадка завышена не
более чем на 2, — но доказано это про догадку, которую алгоритм перестал вычислять в
1995 году. Та, которую он вычисляет теперь, может быть завышена на 3; двух поправок тогда
не хватает, и ответ молча получается неверным.

## Догадка

Цифры — это машинные слова, основание `b = 2^64`. Угадать очередную цифру частного —
самое трудное, поэтому алгоритм D тратит на неё одно аппаратное деление старших цифр.
После *нормализации* (оба операнда умножают на общий множитель, чтобы старшая цифра
делителя стала ≥ `b/2`) в игре оказываются две разновидности этого деления:

```
q̂  = ⌊(две старшие цифры u) / (старшая цифра v)⌋   полное двухцифровое частное (ARM)
q̂ₛ = min(b − 1, q̂)                                 обрезанное до одной цифры (x86, MIX)
```

Две книжные теоремы, обе верные:

- **Теорема A** — догадка никогда не занижена: `q ≤ q̂`
- **Теорема B** — завышена не более чем на 2: `q̂ₛ ≤ q + 2`

Теорема B — про `q̂ₛ`. В 1-м и 2-м изданиях использовалась именно `q̂ₛ`; переработка
1995 года (эпоха MMIX) перевела алгоритм на `q̂`, а теоремы оставила как были. Для `q̂`
граница на единицу больше: `q̂ ≤ q + 3` — **теорема B (Н. Калуджерович, 2026)**,
доказанная в статье и вошедшая в errata Кнута.

## Где разрыв

Шаг **D3** уменьшает догадку **не более двух раз**: ровно то, что нужно для `q̂ₛ ≤ q + 2`,
и на одну поправку меньше, чем нужно для `q̂ ≤ q + 3`. В худшем случае `q = b − 1` даёт
`q̂ = b + 2` — две цифры. Два уменьшения оставляют `b`, то есть `(1,0)` по основанию `b`, —
всё ещё две цифры. Шаг D4 умножает обратно только на *младшую* цифру, а она равна `0`: не
вычитается ничего, и дальше всё идёт вразнос.

Наименьший пример, основание 3:

```
b = 3
u = (1,2,0,0)₃ = 45     истинное частное  q = ⌊45/16⌋ = 2
v =   (1,2,1)₃ = 16     догадка           q̂ = ⌊5/1⌋ = 5 = q + 3 = (1,2)₃
```

D3 срабатывает дважды: `5 → 4 → 3 = (1,0)₃`. D4 умножает на `0`. Ответ неверен. Третье
уменьшение дало бы правильное `2`.

## Демонстрация

[`divbug.c`](divbug.c) прогоняет алгоритм D для произвольного основания тремя способами —
как напечатано в книге (две поправки, D4 берёт `q̂ mod b`), с D3 в виде цикла `while` и с
обрезанной догадкой `q̂ₛ` из 1-го и 2-го изданий, — сверяясь с эталонным делением в
столбик:

```
make && ./divbug          # основание 3, наименьший ломающийся вход
./divbug 65               # любое нечётное основание, до 2^31
```

```
    D3: q^ = 5, r^ = 0
        correction 1 -> q^ = 4, r^ = 1
        correction 2 -> q^ = 3, r^ = 2
        (as printed: the test is not repeated a third time)
        q^ = 3 = (1,0)_3 does not fit in one limb; D4 multiplies by its low limb 0
    -> q = 0, r = 18    *** WRONG ***
       q*v + r = 18, but u = 45

    D3: unsaturated q^ = 5; the saturating div clamps it to b-1 = 2
    D3: q^ = 2, r^ = 3
    -> q = 2, r = 13    correct
```

Затем программа перебирает **все** допустимые деления четырёхразрядных чисел на
трёхразрядные для оснований 3–9:

```
  b = 3   (odd)         945 divisions   as printed:     9 wrong   while loop: 0 wrong   saturating: 0 wrong
  b = 4   (even)       6080 divisions   as printed:     0 wrong   while loop: 0 wrong   saturating: 0 wrong
  b = 5   (odd)       32625 divisions   as printed:    50 wrong   while loop: 0 wrong   saturating: 0 wrong
  b = 7   (odd)      335454 divisions   as printed:   147 wrong   while loop: 0 wrong   saturating: 0 wrong
  b = 8   (even)     785408 divisions   as printed:     0 wrong   while loop: 0 wrong   saturating: 0 wrong
  b = 9   (odd)     1917270 divisions   as printed:   324 wrong   while loop: 0 wrong   saturating: 0 wrong
```

Ломается только напечатанный вариант, только при нечётном основании и ровно на
предсказанных входах. Последний столбец — теорема B в эмпирической форме: с той догадкой,
для которой она доказана, двух поправок хватает при любом основании.

## Почему ошибка пряталась 30 лет

- **Раньше всё было верно.** В 1-м и 2-м изданиях догадка обрезалась, а для `q̂ₛ ≤ q + 2`
  двух поправок хватает. Переработка 1995 года заменила в D3 догадку, но не теоремы, и те
  продолжили доказывать оценку для величины, которую алгоритм уже не вычисляет. Программа
  Кнута на MIX так и осталась верной — сломался только напечатанный алгоритм.
- **На реальном железе не воспроизвести.** Нужно **нечётное** `b`, причём
  `v_{n-1} = u_n = (b−1)/2` и `u_{n-1} = b−1`. Настоящие машины работают с `b = 2^32`
  или `2^64`.
- **Реализаторы писали цикл.** Кнутовское *«повторите эту проверку, если r̂ < b»*
  читается как *«ещё один раз»*; почти все написали *while*, а он делает третью поправку
  и тем самым закрывает дыру.

## LLVM

`APInt.cpp` следует тексту буквально (два `if`) и до сих пор проверяет `q̂ == b` —
опечатку TAOCP, исправленную в 2005-м на `q̂ ≥ b`. При чётном `b` догадка доходит лишь до
`b + 1`, и этот случай как раз отлавливается второй проверкой D3, так что LLVM считает
правильно — но по причине, не доказанной ни в книге, ни в коде. Калуджерович отправил PR,
не меняющий поведения, чтобы привести код к исправленному тексту.

## Итог

Отправлено 14 мая 2026, вошло в errata Кнута 9 июня 2026, в печати появится в 53-м тираже
второго тома, где `q̂ₛ ≤ q + 2` уступит место `q̂ ≤ q + 3`. Награда — чек на один
шестнадцатеричный доллар, `0x$1.00` = $2.56, в Банке Сан-Серифа.

> *«Особенно рад этой поправке: мне кажется, читатели второго тома TAOCP смотрят на
> алгоритм 4.3.1 D чаще, чем на любой другой!»* — Кнут
