# Ошибка в алгоритме D

Markdown-копия статьи Новака Калуджеровича **[A long division story](A-long-division-story.md)**
([оригинал](https://kolja.rs/algorithm-d)) — об ошибке в алгоритме 4.3.1D из «Искусства
программирования» Кнута (деление в столбик), прожившей с 1995 по 2026 год.

## Суть в одном абзаце

Алгоритм D делит огромные числа по одной цифре. Каждую цифру частного он *угадывает* по
одним лишь старшим цифрам, а потом поправляет догадку не более двух раз. В книге
доказано, что догадка может оказаться завышенной на 3. Двух поправок не всегда хватает —
и на таких входах алгоритм молча выдаёт неверный ответ.

## Как это работает

Большое число хранится как массив машинных слов — это цифры по основанию `b = 2^64`.
Делят в столбик, по цифре за шаг. Трудное здесь — угадать очередную цифру, и алгоритм D
оценивает её одним аппаратным делением старших цифр:

```
q̂ = ⌊(две старшие цифры u) / (старшая цифра v)⌋
```

Ошибку ограничивают две теоремы — после *нормализации* (оба операнда умножают на общий
множитель, чтобы старшая цифра делителя стала ≥ `b/2`):

- **Теорема A** — догадка никогда не занижена: `q ≤ q̂`
- **Теорема B** — завышена не более чем на 3: `q̂ ≤ q + 3`

Дальше шаг **D3** проверяет догадку по второй цифре делителя и уменьшает её на единицу —
**не более двух раз**, если читать формулировку книги буквально. Считается, что после
этого догадка (а) завышена не более чем на 1 и (б) занимает **одну цифру**, так что шаг
D4 может внести её обратно дешёвым умножением на однозначное число.

## Где разрыв

D3 исправляет 2, теорема B допускает 3.

В худшем случае `q = b − 1` даёт `q̂ = b + 2` — две цифры. Два уменьшения оставляют `b`,
то есть `(1,0)` по основанию `b`, — всё ещё две цифры. D4 умножает на *младшую* цифру, а
она равна `0`: не вычитается ничего, и дальше всё идёт вразнос.

Наименьший пример, основание 3:

```
b = 3
u = (1,2,0,0)₃ = 45     истинное частное  q = ⌊45/16⌋ = 2
v =   (1,2,1)₃ = 16     догадка           q̂ = ⌊5/1⌋ = 5 = q + 3 = (1,2)₃
```

D3 срабатывает дважды: `5 → 4 → 3 = (1,0)₃`. D4 умножает на `0`. Ответ неверен. Третье
уменьшение дало бы правильное `2`.

## Демонстрация

[`divbug.c`](divbug.c) реализует алгоритм D для произвольного основания и прогоняет его
двумя способами — как напечатано в книге (D3 поправляет не более двух раз, D4 берёт
`q̂ mod b`) и с D3 в виде цикла `while`, — сверяясь с эталонным делением в столбик:

```
make && ./divbug          # основание 3, наименьший ломающийся вход
./divbug 65               # любое нечётное основание, до 2^31
```

```
    D3: q^ = 5, r^ = 0
        correction 1 -> q^ = 4, r^ = 1
        correction 2 -> q^ = 3, r^ = 2
        (as printed: the test is not repeated a third time)
        q^ = 3 = (1,0)_3 does not fit in one limb; D4 multiplies by its low limb 0
    -> q = 0, r = 18    *** WRONG ***
       q*v + r = 18, but u = 45
```

Затем программа перебирает **все** допустимые деления четырёхразрядных чисел на
трёхразрядные для оснований 3–9. Нечётные основания ломаются ровно на предсказанных
входах, чётные — никогда, а вариант с `while` верен всегда:

```
  b = 3   (odd)         945 divisions   as printed:     9 wrong   while loop: 0 wrong
  b = 4   (even)       6080 divisions   as printed:     0 wrong   while loop: 0 wrong
  b = 5   (odd)       32625 divisions   as printed:    50 wrong   while loop: 0 wrong
  b = 7   (odd)      335454 divisions   as printed:   147 wrong   while loop: 0 wrong
  b = 8   (even)     785408 divisions   as printed:     0 wrong   while loop: 0 wrong
  b = 9   (odd)     1917270 divisions   as printed:   324 wrong   while loop: 0 wrong
```

## Почему ошибка пряталась 30 лет

- **Раньше всё было верно.** В 1-м и 2-м изданиях догадка обрезалась до `b − 1` — так
  работает `div` на x86 и в кнутовской машине MIX; для обрезанной догадки `q̂ ≤ q + 2`, и
  двух поправок хватает. Переработка 1995 года (эпоха MMIX) заменила D3 на необрезанную
  двухцифровую догадку (`div` в духе ARM), но теоремы под неё не поправила. Программа
  Кнута на MIX так и осталась верной — сломался только напечатанный алгоритм.
- **На реальном железе не воспроизвести.** Нужно **нечётное** `b`, причём ровно
  `v_{n-1} = u_n = (b−1)/2` и `u_{n-1} = b−1`. Настоящие машины работают с `b = 2^32`
  или `2^64`.
- **Реализаторы писали цикл.** Кнутовское *«повторите эту проверку, если r̂ < b»*
  читается как *«ещё один раз»*; почти все написали *while*, а он делает третью поправку
  и тем самым закрывает дыру.

## LLVM

`APInt.cpp` следует тексту буквально (два `if`) и до сих пор проверяет `q̂ == b` —
опечатку TAOCP, исправленную в 2005-м на `q̂ ≥ b`. При чётном `b` догадка доходит лишь до
`b + 1`, и этот случай как раз отлавливается второй проверкой D3, так что LLVM считает
правильно — но по причине, не доказанной ни в книге, ни в коде. Калуджерович отправил PR,
не меняющий поведения, чтобы привести код к исправленному тексту.

## Итог

Отправлено 14 мая 2026, вошло в errata Кнута 9 июня 2026, в печати появится в 53-м тираже
второго тома. Исправленная оценка теперь называется **теоремой B (Н. Калуджерович, 2026)**.
Награда — чек на один шестнадцатеричный доллар, `0x$1.00` = $2.56, в Банке Сан-Серифа.
